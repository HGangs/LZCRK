# 问题记录

> 记录开发过程中的报错、原因与解决办法。

## 1. 数据丢失（2026-10-31）

- **现象**：打开工作台后数据为空。
- **原因**：数据存 localStorage，按「协议 + 域名 + 端口」隔离。用随机端口的本地服务访问，端口一变就是空库；同时桌面客户端 userData 曾被自检脚本删除。
- **解决**：从浏览器 leveldb 直接解析恢复（SSTable footer → data block，snappy 解压）；新增固定端口启动脚本与一键恢复页。
- **教训**：禁止删除任何浏览器/客户端 userData 目录；数据恢复走同源写入。

## 2. 启动脚本闪退（2026-11-01）

- **现象**：双击 `启动工作台.cmd` 黑窗一闪而过。
- **原因**：脚本用 `where python` 找到的是 Windows 应用商店别名（非真实解释器），执行即失败。
- **解决**：改为绝对路径优先探测（`%USERPROFILE%\.workbuddy\...\python.exe` 等），找不到时提示改用桌面客户端。

## 3. 模板字符串里写 `%` 导致格式化报错（v4.16 文档脚本）

- **现象**：`ValueError: unsupported format character ';'`。
- **原因**：用 Python `%` 格式化拼接 HTML/CSS，CSS 里的 `%` 被当成格式符。
- **解决**：改用占位符字符串替换（`__A__` → 内容）。

## 4. heredoc 写日志被安全策略拦截

- **现象**：`Command blocked for security: Known Windows LOLBin`。
- **原因**：命令文本里包含解释器 + 脚本组合，触发规则。
- **解决**：改用 Write 工具直接写文件。

## 5. 删完台账，调拨记录还在（2026-11-18，用户报）

- **现象**：清空出库/入库台账后，到「出库物资调拨 → 调拨记录」仍能看到原先的调拨单据。
- **原因**：`deleteDoc()` 只按 `r.docNo !== docNo` 删除流水；而调拨流水的 `docNo` 是 `DB-日期-序号`，靠 `srcDocNo` 指向来源出库单，因此源单删掉后调拨流水全部残留。这些残留仍带着 `projectId`，会继续占用项目持有量，属于**孤儿数据**。
- **解决**：
  1. `deleteDoc()` 改为同时删除 `r.transfer && r.srcDocNo === docNo` 的流水，并在确认弹窗与操作日志里写明「该单已发起 N 张调拨（M 条流水），会一并清除」。
  2. 新增 `orphanTransferRecords()` 与调拨记录页的「清理失效调拨（N 张）」按钮（仅检测到孤儿时出现），用于清理修复前已产生的历史残留；清理只删这些调拨流水，仓库库存不动，项目持有按调拨量回滚。
  3. 新增 `tests/t20.js` 覆盖：删单连带清理、库存与项目持有回滚、失效调拨检测与清理、误删保护。
- **验证**：t20 全绿；删除后 480 → 500（回滚），项目持有 1462/220 → 1452/210（回滚），调拨流水 2 → 0。

## 6. 抽屉 / 折叠点击没反应（v4.19 开发中）

- **现象**：项目清单点行不弹抽屉、点行政区组头不折叠，`state` 无变化。
- **原因**：新增的 4 段 click 分支（`plDrawer` / `plDrawerClose` / `savePlDrawer` / `plGroupToggle`）被插到了 `document.addEventListener('change', ...)` 回调里（因为锚点 `plOwner`/`plUnit` 属于 change 监听），click 事件永远走不到。
- **解决**：把这 4 段整体移回 click 监听器（`resetDB` 分支之后）。排查手法：在分发入口打 `act` 日志，再二分插入 `console.log('reach N')` 定位提前返回点。

## 7. 记录页删除按钮不渲染（v4.19）

- **现象**：`can('records','delete')` 为 true，但表格里没有删除按钮。
- **原因**：行模板替换命中了同字符串的另一处（物料明细页的流水表），记录页模板未改动；同时 `delRecord` 动作与物料明细已有分支重名，会被先命中的旧分支拦截。
- **解决**：还原误改位置；记录页按钮改用独立动作 `delRecRow`，事件分支同步改名；表头补第 10 列。

## 8. CloudBase 测试域名访问 HTML 被「风险提醒」拦截（2026-11-19）

- **现象**：访问 `*.tcloudbaseapp.com` 或 `*.webapps.tcloudbase.com` 显示"风险提醒 / 仅供开发测试 / 当前访问量已达上限"，需等 3 秒点"确定访问"，且跳回后仍可能再拦。
- **原因**：国内备案要求，CloudBase 默认测试域名不允许直接对外提供网页服务。
- **解决**：改用 WorkBuddy 应用托管域名（`*.app.workbuddy.host`）；若必须用 CloudBase 域名，需绑定已备案的自定义域名。

## 9. GitHub 集成无法创建仓库（403）

- **现象**：`create_repository` 返回 `403 Resource not accessible by integration`。
- **原因**：WorkBuddy 的 GitHub 连接是 App 集成，未授予 `Administration: write`（建仓）权限；已有仓库可读写。
- **解决**：改用已有仓库（用户已有 `HGangs/LZCRK`）；该仓库为 public，需先改私有再推送，避免暴露 Publishable Key 与内部数据。

## 10. 云端为空时本地 seed 数据可能覆盖真实数据

- **风险**：首次打开云端域名会 seed 演示数据，若此时拉取失败而仍允许推送，会把云端真实数据覆盖成演示数据。
- **解决**：引入 `cloud.pulled` 闸门——只有成功拉到云端状态（有数据或确认云端为空）才允许推送；拉取失败时徽标显示「同步失败」，改动只留本地。

## 11. 云托管 OperationMode 合法值只有 5 个（2026-11-19）

- **现象**：想把常驻服务改成弹性伸缩，先后传 `scaleByTraffic` / `autoScale` / `scale` 均报「操作模式参数不合法」。
- **原因**：TCB `ModifyCloudRunServer` 的 `OperationMode` 只有 `noScale | condScale | alwaysScale | custom | manualScale` 五个值；MCP 层只透传字符串，本地文档与 MCP schema 都没写枚举。
- **解决**：`alwaysScale`（持续运行，固定副本）→ `condScale`（按负载自动伸缩，MinNum=0 时可缩到 0）。枚举来源：腾讯云 API 436 数据结构文档。

## 12. GitHub 连接器只能读，不能写（2026-11-19）

- **现象**：仓库改回 public 后，读接口正常（空仓库返回 `409 Git Repository is empty`），但 `create_or_update_file` 返回 `403 Resource not accessible by integration`。
- **原因**：WorkBuddy 的 GitHub 连接器（上游 `api.githubcopilot.com`）对应的 GitHub App 只被授予读权限，没有 `Contents: Read and write`。这与仓库可见性无关——私有 404、公开仍 403。
- **旁路尝试**：本地 `git push` 不可行——直连 github.com:443 与 ssh.github.com:443 均超时，环境代理 `127.0.0.1:45564` 对 github 返回 502。
- **可行的替代**：① 用户网页上传 `恢复/代码仓库上传包.zip`；② 给 App 提升 Contents 写权限（若集成方允许）。
- **可复用技巧**：本地可直接调用 MCP 的 Streamable HTTP 接口（`CODEBUDDY_MCP_CONFIG` 里的 url + `Authorization` + `X-WorkBuddy-MCP-Context`，先 `initialize` 拿 `Mcp-Session-Id`，再 `tools/call`），从而让脚本推送文件内容而不经过对话上下文。

## 13. git 连 GitHub 报 CRYPT_E_NO_REVOCATION_CHECK（2026-11-19）

- **现象**：`git ls-remote https://github.com/...` 报 `schannel: next InitializeSecurityContext failed: CRYPT_E_NO_REVOCATION_CHECK (0x80092012) - 吊销服务器无法检查吊销状态`；`curl https://api.github.com` 返回 000。
- **误判**：看起来像"墙"或防火墙拦端口，实际 `TCP 443` 是通的（`/dev/tcp` 可连），是 Windows schannel 无法访问 CRL 吊销服务器导致 TLS 握手失败。
- **解决**：① `curl --ssl-no-revoke` 立即通（返回 200）；② git 的 `http.schannelCheckRevoke=false` 在本机 2.55 版无效，改用 `git config --global http.sslBackend openssl` 后 `ls-remote` 正常。
- **注意**：环境变量 `HTTP_PROXY/HTTPS_PROXY=127.0.0.1:45564` 是 WorkBuddy 注入的内部代理，对 github 返回 502/000，git/curl 必须 `env -u` 清掉再走直连。

## 14. GitHub 连接器只读，SSH 绕过（2026-11-19）

- **结论**：WorkBuddy 的 GitHub 连接器对应 GitHub App 只申请了读权限，`/settings/installations` 只能改"仓库范围"，改不了权限（App 权限由集成方定义）。写操作固定 `403 Resource not accessible by integration`。
- **绕过方案（已完成）**：
  1. `ssh-keygen -t ed25519 -f ~/.ssh/id_wms -N ""`
  2. 浏览器（ego-browser）打开 `https://github.com/settings/ssh/new`，填 title + 公钥，提交
  3. `~/.ssh/config`：`Host github.com / HostName ssh.github.com / Port 443 / IdentityFile ~/.ssh/id_wms`（本机 22 端口关闭，443 可用）
  4. `git remote add origin git@github.com:HGangs/LZCRK.git && git push -f origin HEAD:main`

## 15. 局部变量遮蔽全局 `uid()` 导致划拨报错（2026-11-21）

- **现象**：保存划拨时抛 `TypeError: uid is not a function`。
- **原因**：`saveAlloc` 里用 `const uid = $('#alloc-unit').value` 存单位 id，遮蔽了全局 `uid()` 主键生成函数，后面 `uid('r')` 直接失败。
- **解决**：局部变量改名 `allocUnitId`。同类命名（`uid` / `id` / `mod`）在单文件全局函数环境下要避让。

## 16. 批量选择弹窗里设备名不显示（2026-11-20）

- **现象**：弹窗只显示复选框，看不到设备名称。
- **原因**：全局 `input` 宽度规则让 `input[type=checkbox]` 撑满整行，`span.nm`（flex:1）被压到 0 宽。
- **解决**：`.pm-item input[type=checkbox]{width:15px;height:15px;flex:0 0 15px}` 固定尺寸。
- **教训**：单文件全局样式下，任何 `input` 都可能被表单规则影响，自定义列表里的 checkbox 必须显式定宽。

## 17. 移动端抽屉里导航只剩图标（2026-11-20）

- **现象**：≤768px 打开抽屉，导航只有图标，没有文字。
- **原因**：`@media (max-width:900px)` 有一条 `.brand-name,.nav-group,.nav-item span,...{display:none}`（为 60px 图标条设计），级联到 768px。
- **解决**：在 768 断点内显式覆盖回 `display:block/inline-block`，并改回 `justify-content:flex-start`。
